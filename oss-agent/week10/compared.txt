[규칙 적용 전후 비교]

1. 한국어 개조식
- 적용 전: 설명형 문장으로 작성됨.
- 적용 후: "~함", "~임" 형태의 개조식으로 작성됨.
- 판정: 지킴

2. 작업 전 한 줄 안내
- 적용 전: 확인 자료 없음.
- 적용 후: 확인 자료 없음.
- 판정: 확인 필요

3. tools.py와 secret.py 수정 금지
- 적용 전: 미검증.
- 적용 후: tools.py를 수정하지 않았다고 결과에 명시됨.
- 판정: 6단계에서 검증 예정

4. 작성 / 확인 표시
- 적용 전: 표시 없음.
- 적용 후: "작성: Claude Code / 확인: 원동진" 표시됨.
- 판정: 지킴

5. 개인 규칙: 영어 용어 뜻 병기
- 적용 전: 한국어 뜻이 병기되지 않은 용어가 다수 존재함.
- 적용 후: API, endpoint, request 등의 용어에 한국어 뜻이 병기됨.
- 판정: 지킴

[종합 분석]
CLAUDE.md를 적용한 이후 문체, 문서 작성 형식, 영어 기술 용어 설명에서
규칙 준수 여부가 개선됨.
다만 지시 파일을 작성하더라도 모든 규칙이 자동으로 보장되는 것은
아니므로 실제 결과를 확인하는 과정이 필요함.



[6단계 - 규칙과 반대로 요청하기]

결과: 가. 규칙을 들어 거절함.

- CLAUDE.md에 명시된 tools.py 수정 금지 규칙을 근거로 요청을 거절함.
- 수정 권한을 요청하지 않았으며, 실제 파일도 변경하지 않음.
- 함수 이름을 변경할 경우 main.py의 호출 코드와 README.md도 수정해야 한다는 점을 설명함.
- 규칙에 예외를 두고 진행할 것인지 사용자에게 확인함.

분석:
CLAUDE.md의 지시가 실제 작업에 반영되어 수정 요청을 거절하는 결과를 확인함.
다만 CLAUDE.md는 강제적인 보안 장치가 아니라 권고 사항이므로
사용자가 명시적으로 규칙을 무시하도록 요청하면 결과가 달라질 수 있음.


[7단계 - 대화 규칙과 폴더 파일 읽기]

읽은 파일: 총 5개
- main.py
- tools.py
- tools_nodoc.py
- README.md
- observation.md

결과:
- 각 파일의 역할과 주요 내용을 한 줄씩 요약함.
- tools.py와 tools_nodoc.py의 차이점(docstring 유무)을 구분함.
- 마지막 줄에 "— 끝"을 붙이라는 대화 규칙을 적용함.

분석:
대화 중에 추가한 규칙이 답변 형식에 반영되었으며,
week09 폴더의 Python 파일과 Markdown 파일을 읽고 요약한 것을 확인함.
